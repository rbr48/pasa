PASA Sentinel Documentation

v3.7.13 (Build 78) Android 8.0 – 16 Knox Device Owner Updated Sept 2026

PASA Sentinel is a sovereign Knox-Grade Android Device Owner anti-theft and mobile defense system. It operates at the highest supervisor privilege of Android OS — completely independent of Google Play Services, Firebase, or any cloud telemetry infrastructure.

Zero-Storage Architecture

All surveillance media (photos, GPS, audio) is streamed direct to your private Telegram bot and immediately shredded from device RAM. Our servers store exactly 0 bytes of your evidence — ever.

# Core Principles

  • Zero Google Play Dependencies — No Firebase, no GCM, no Play Services, no crash analytics. Works on any Android 8.0+ device.
  • Knox-Grade Device Owner Permanence — Installed once via ADB. The OS grays out Uninstall and Force Stop. Cannot be removed without physical ADB access.
  • Direct-to-Telegram C2 — Your botToken and ownerChatId never leave your device. Sovereign Mode communicates directly with api.telegram.org.
  • Ed25519 Offline Licensing — Licenses verified 100% offline via hardware-backed Ed25519 cryptography. No server round-trip required per command.
  • Air-Gapped SMS Fallback — Even with cellular data and Wi-Fi completely disabled, TOTP-authenticated SMS commands trigger GPS, camera, and lockdown.

Quick Start — 5 Minutes to Deployment

Beginner Friendly ~5 min
Prerequisites

Before starting: (1) Remove all Google accounts from the device. (2) Perform a factory reset if any accounts were previously linked. (3) Skip all account setup screens during first boot. (4) Enable Developer Options and USB Debugging.

# Step 1: Download PASA Sentinel APK

browser / adb
# Direct download from official server
https://pasa.izhaanintellect.fun/releases/pasa-latest.apk

# SHA-256 verification (ALWAYS verify before installing)
b282efb02bbcd54bc9941a5964c8c7d0fdf52490f1496469c97434c60a7f144e

# Install via ADB (sideload)
adb install -r pasa-latest.apk

# Step 2: Set Device Owner via ADB

Critical — Run Once

This command must be run ONCE on a device with NO Google accounts signed in. If accounts are present, the command will fail with java.lang.IllegalStateException.

adb shell
adb shell dpm set-device-owner \
  com.izhaanintellect.pasa/.admin.PasaDeviceAdmin

# Expected success output:
Success: Device owner set to package com.izhaanintellect.pasa

# Step 3: Create Your Telegram Bot

  1. Open Telegram and message @BotFather
  2. Send /newbot → follow prompts → receive your bot token
  3. Message your new bot to initiate the chat
  4. Get your Chat ID from @userinfobot or the bot's getUpdates API response

# Step 4: Initial Setup in PASA

Open PASA Sentinel on the device. In the Setup Activity:

  1. Enter your Bot Token (from @BotFather)
  2. Enter your Owner Chat ID
  3. Set a Master Password (used for sensitive commands)
  4. Tap Arm PASA Sentinel
Success

PASA will send a confirmation message to your Telegram bot: 🛡️ PASA SENTINEL v3.7.13 // ARMED & OPERATIONAL. Send /status to verify all systems are active.

# Step 5: Arm Hardware Escrow Token (PIN Reset)

This is required for remote PIN reset on Android 14–16 (Google removed the old API). Perform this on first physical unlock after setup:

telegram
# Arm the hardware escrow token
/set_os_pin 123456

# The token auto-arms on next physical device unlock.
# After arm confirmation, test remote PIN reset:
/set_os_pin <new_pin>

Windows Setup Kit — Guided Wizard

The PASA Windows Setup Kit is a guided 6-step PowerShell wizard designed for non-technical users. It automatically downloads ADB, installs the APK, and sets Device Owner — no command line knowledge required.

  1. Download the Setup Kit
    Download PASA-Device-Owner-Setup-Kit.zip from the official server: /releases/PASA-Device-Owner-Setup-Kit.zip. Extract to any folder.
  2. Remove Google Accounts from Device
    Go to Settings → Accounts → Remove all Google accounts. This is mandatory. If Google accounts are present, Device Owner provisioning will fail.
  3. Enable USB Debugging
    Settings → About Phone → tap Build Number 7 times → Developer Options → USB Debugging → Enable. When prompted on phone, tap "Allow" for the computer.
  4. Run the Setup Wizard
    Double-click PASA Device Owner Setup.bat. The wizard will automatically download ADB platform-tools, install the APK, and run the Device Owner command.
  5. Confirm Success
    The wizard displays: Success: Device owner set to package com.izhaanintellect.pasa. Open PASA on the device to complete setup.

Air-Gapped Cellular SMS Fallback

Offline Operation

When cellular data is blocked, jammed, or Airplane Mode is engaged — cellular radio remains registered with nearby towers. PASA intercepts incoming SMS at priority 999 even on the lockscreen.

# SMS Command Syntax

sms format
# Format: PASA <6-digit-TOTP> <command>

PASA 419582 /locate
PASA 419582 /lock
PASA 419582 /usb_lock on
PASA 419582 /set_master_pin newpass123
PASA 419582 /wipe_confirm

# TOTP Enrollment

Send /smssetup in Telegram. PASA will:

  1. Generate a unique 20-byte TOTP secret
  2. Send you a scannable QR code for any authenticator app (Google Authenticator, Aegis, etc.)
  3. Confirm enrollment — TOTP codes now authenticate SMS commands

# Supported SMS Commands

All critical commands work air-gapped via SMS: /locate, /lock, /unlock, /usb_lock, /camera_lock, /bluetooth_lock, /mic_mute, /snap, /reboot, /wipe, /wipe_confirm, /sim_tray_lock, /set_master_pin, /fakeshutdown, /wake, /antitamper, /autolock, /wifi_connect, /security_audit, /sms_help.

SMS responses are delivered back via the same SIM that received the command (dual-SIM aware).

Autonomous Sensor Traps & Physical Defense

PASA's trap system operates entirely autonomously — no internet connection or Telegram access is required for traps to fire. Each trap activates, captures evidence, and dispatches it when connectivity is restored.

# Kinetic Snatch Trap

Continuous accelerometer monitoring with vector magnitude threshold of >2.65G (26.0 m/s²).

When triggered: (1) Device locks immediately, (2) Knox Kiosk Lost Mode activates, (3) Front camera captures perpetrator mugshot, (4) GNSS fix is acquired, (5) Telegram SOS alert with photo + GPS pin.

telegram
/trap snatch on       # Enable (recommended always-on)
/trap snatch off      # Disable
/trap snatch status   # Check current state

# Cryptographic SIM Tray Lockout

When /sim_tray_lock arm is active and an unauthorized SIM is inserted:

  1. Lockscreen PIN rotated to a random 8-digit secret via Knox hardware escrow token
  2. Secret PIN transmitted only to owner via Telegram
  3. All third-party apps suspended via setPackagesSuspended() — phone becomes unusable
  4. Knox Kiosk Lost Mode engaged, biometrics disabled
  5. Factory reset blocked
  6. Reversible only via /sim_tray_lock release from owner Telegram

# Foreign SIM Auto-SMS (SIM Swap Guard)

Configure a recovery phone number with /sim_lock phone +8801XXXXXXXXX. When an unauthorized SIM is inserted, PASA silently sends an emergency SMS to your recovery number containing:

  • Device IMEI and model
  • Carrier name of the new SIM
  • Google Maps GPS link
  • The caller ID of the thief's new SIM number is exposed to your recovery contact

Duress PIN & Sterile Sandbox Decoy OS

The Duress PIN is a secret alternate PIN that, when entered by a coercer on the lockscreen, unlocks the device while silently triggering a covert defense sequence.

# Duress Unlock Sequence

  1. Coercer types the Duress PIN on lockscreen keyboard
  2. Accessibility Service detects the match silently
  3. Device unlocks via hardware escrow (coercer thinks normal unlock)
  4. Sterile Sandbox Decoy OS activates: Banking apps, crypto wallets, and private messengers instantly vanish from launcher via setApplicationHidden()
  5. Swipe-up dismiss gesture dispatched + GLOBAL_ACTION_HOME
  6. Front camera captures coercer mugshot silently
  7. GNSS GPS fix acquired
  8. Emergency SOS Telegram alert with mugshot + location dispatched
telegram
/duress_pin 4829   # Set duress PIN (requires master password)
Security Note

The Duress PIN must be different from your real OS PIN. Do not use sequential numbers (1234) or birthdays. The Accessibility Service operates at OS privilege level — no app on the device can detect or block this mechanism.

Advanced Mobile Cyber Defense Suite

PASA's Cyber Defense Suite is a collection of 8 advanced threat mitigation modules that operate at Device Owner kernel level to neutralize digital attack vectors independently of anti-theft operations.

# Accessibility Trojan Shield (/a11y_shield)

Blocks overlay attacks from malicious accessibility services. Prevents unauthorized apps from using Accessibility APIs to intercept keystrokes, overlay phishing screens on banking apps, or automate UI interactions without consent.

# Anti-2G / IMSI-Catcher Shield (/anti_2g)

Forces LTE/5G-only cellular operation. IMSI catchers (Stingrays) operate by broadcasting a stronger 2G signal to force device downgrade to unencrypted GSM. With Anti-2G enabled, the device will not register on 2G/EDGE networks regardless of signal strength.

# Locked-State USB Killswitch (/usb_autolock)

Automatically severs USB data pins whenever a cable is inserted while the device is locked. Even if a forensic box (Cellebrite, GrayKey, UFED) is connected before the device is powered off, data pins are severed on next lock. AC power charging is preserved.

# Cryptographic SIM Tray Lock (/sim_tray_lock)

When armed, any unauthorized SIM insertion triggers a full Knox brick-mode sequence: escrow PIN rotation, app suspension, Kiosk Lost Mode, biometrics disabled, factory reset blocked. The device becomes a complete brick to the unauthorized handler — PASA itself remains 100% active.

# Ransomware Canary Guard (/canary_guard)

Plants invisible decoy files (canary files) in critical directories. Monitors for unauthorized modification or encryption. If a ransomware process touches the canary files, PASA immediately alerts the owner and can trigger lockdown to contain the attack.

# Crypto Clipper Guard (/clipper_guard)

Real-time clipboard monitoring for cryptocurrency wallet address patterns (Bitcoin, Ethereum, BNB, etc.). When an address is detected in clipboard, it's verified against the user's registered wallets. Substitution by malware triggers an immediate alert.

# OTP Interception Guard (/otp_guard)

Monitors for unauthorized third-party apps reading SMS OTP messages. Alerts owner when a non-system app intercepts a one-time password SMS, which is the primary attack vector for SIM-swap fraud and banking trojans.

# Ed25519 Offline Verification Architecture

PASA's licensing operates without any server round-trip per command:

  1. At activation, server issues a signed Ed25519 certificate containing: device hash, tier, expiry timestamp
  2. Client verifies this certificate against the hardcoded Ed25519 public key — completely offline
  3. Certificates rotate automatically every 7 days (fetched in background)
  4. If revoked on server, next rotation delivers a null certificate → all premium commands lock
Privacy Architecture

The licensing server never receives your device IMEI or hardware serial. Only an irreversible SHA-256 hash of SHA256(deviceId:licenseKey) is transmitted. Your hardware identity is never stored.

Zero-Storage & Zero-Data Architecture

# RAM-Only Evidence Pipeline

Every piece of surveillance evidence follows this exact lifecycle:

  1. Captured in device memory (CameraX frame, AudioRecord PCM, GNSS coordinates)
  2. Transmitted directly to api.telegram.org via multipart POST over TLS 1.3
  3. If VPS relay is used, multer.memoryStorage() ensures the buffer exists only in Node.js process RAM — never written to disk
  4. Immediately after transmission: photoFile.delete() + RAM buffer zeroed
  5. Result: 0 bytes persist on VPS or device storage

# Zero Credential Transmission

Your botToken and ownerChatId are stored exclusively in Android's EncryptedSharedPreferences (AES-256-GCM backed by Android Keystore). They are never transmitted to our VPS control plane under any circumstances.

Docs›Provisioning›OEM Nuances

OEM-Specific Provisioning Notes

# Samsung (Knox)

  • Samsung Knox counter is not tripped by Device Owner provisioning
  • Disable Samsung accounts (not just Google) before running DPM command
  • One UI may show "Managed by your organization" in Settings — this is expected
  • If Device Care shows optimization suggestions, PASA is still protected

# Xiaomi / MIUI / HyperOS

  • Enable "Install via USB" in Developer Options
  • Remove Mi Account AND Google Account before provisioning
  • MIUI's aggressive battery optimization may kill background services — set PASA to "No restrictions" in Battery Settings
  • HyperOS 2.0: Additional authorization may be required in Security Center

# Google Pixel

  • Most compatible — reference Android implementation
  • All APIs including StrongBox are fully available
  • USB Debugging prompt appears on first ADB connection — approve it

# OnePlus / OxygenOS / ColorOS

  • Remove OnePlus/OPPO accounts in addition to Google accounts
  • Battery optimization: App Info → Battery → Background Activity → Allow
  • Aggressive RAM management may require "Lock" in Recents — PASA watchdog handles most scenarios
